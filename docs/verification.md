# Verification

This is a concise summary of how the project is verified. The detailed logs live outside the
repository.

| Check | Command | Expectation |
| --- | --- | --- |
| Tests | `python -m pytest -q` | all pass |
| Lint | `ruff check .` | no findings |
| Format | `ruff format --check .` | no files would change |
| Art | `python art/generate_art.py --check` | committed art matches the generator |
| Build | `python -m build` | wheel and sdist built (outputs git-ignored) |
| End to end | `scripts/e2e-smoke.sh` | fresh venv installs the wheel and the offline flow passes |
| Secrets | `scripts/scan-secrets.sh` | exit 0, no findings beyond the audited baseline |

## End-to-end smoke

`scripts/e2e-smoke.sh` builds a wheel and sdist into a fresh run directory, creates a fresh
virtual environment, installs the wheel and then:

1. runs `mascot-wardrobe --help`;
2. generates from `examples/mascot.png` twice and compares manifest and asset hashes and mtimes;
   its own temporary inventory home contains six garments with stable numbers after both runs;
3. selects at 3, 10, 17, 21, 28 and 35 C (one per BR category) and at 77 F (warm);
4. runs `demo --channel telegram` twice and checks the second run is `unchanged` with identical
   hashes and mtimes.

It never passes `--live-weather`, so it uses no network for weather. Prerequisites: the
interpreter is `$PYTHON`, else `.venv/bin/python` when executable, else `python3`, and it must
have the build module (`pip install build`); the script stops with a message otherwise. Set
`MASCOT_WARDROBE_EVIDENCE_DIR` to choose where outputs go; by default a new temporary directory
is used. Each run creates its own `run.*` directory inside it with `mktemp -d`, never touches
existing content and keeps the run directory afterwards.

Before the first installed CLI command, the smoke script sets `MASCOT_WARDROBE_HOME` to its
own run directory. Pytest also redirects inventory data and isolates each test, including
subprocesses, so verification does not register example garments into a real user inventory.

## Source distribution

`tests/test_sdist.py` builds the real sdist (`python -m build --sdist`) and inventories it with
`tarfile`: public docs, art, assets, examples, scripts, plans, tests, CI and the secret baseline
must be present, private or generated paths absent, every relative README link must resolve inside
the sdist, and a wheel built from the unpacked sdist must be runtime-only. `scripts/*` need a git
checkout (`git ls-files`) and are checkout-only in an extracted sdist; tests that need git or the
repo `.venv` skip with a clear reason there.

## Secret scanning

`scripts/scan-secrets.sh [REPORT]` runs `detect-secrets-hook --baseline .secrets.baseline` over tracked
files plus untracked files that are not ignored. The hook exits non-zero on new findings. The
baseline was generated by detect-secrets and audited: it contains no real secrets. The optional
report holds only the status, exit code, file and finding counts and one `type at file:line` line
per finding; it never contains raw hook output or context lines (the full output goes to the
terminal). `detect-secrets` is pinned to 1.5.0 in the `dev` extra and in CI.

## Test-driven development

New or changed behavior was written test first, with the failing and passing runs saved outside
the repository. Traceability from each acceptance criterion to tests is in `traceability.md`.
