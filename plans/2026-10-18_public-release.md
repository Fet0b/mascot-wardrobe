# Plan: mascot-wardrobe public release

Spec: `docs/specs/public-release.md` (AC-1..AC-28). All decisions in the spec's "Pre-approved decisions" section are final. Nothing here publishes, pushes, installs a service or contacts a real account.

## Context

The prototype (`src/mascot_wardrobe`, 34 tests) works but is not publishable: 9 tests fail because code and tests hardcode a machine-specific scratch root (an absolute path under the maintainer's home cache) and a fallback project root; the distribution is named `mascot-wardrobe-ddd`; the HTTP sandbox header contains a personal mascot name; docs, error messages and category labels are Portuguese; `docs/wardrobe-tests.txt` and `wardrobe/NOTAS.md` hold private-specific evidence; there is no README, license, CI, art or scanner. Baseline logs live in the cache dir outside the repo (pytest 25 pass / 9 fail, ruff check 35 findings, ruff format 10 files).

## Approach

Three cohesive steps, each followed by explicit verification, strict TDD for each new or changed behavior (write test, run to see the expected RED, minimal change, run GREEN, one vertical slice at a time; existing passing characterization tests are baseline, not fake RED). RED/GREEN logs are saved in the cache dir, never in the repo.

Layering stays pragmatic and honest: `domain` (pure values), `application` (use cases; `safe_output`, `prepare_wardrobe`, `select_outfit`, `export_outfit`, `sync_sandbox`), adapters (`wardrobe` Pillow compositor behind the `Renderer` protocol, `channels`, `infrastructure` profiles + weather), `interfaces.cli`. Existing public imports (`mascot_wardrobe.application`, `.wardrobe.WardrobeAgent`, `.channels.*`, `.domain.models.*`, `.infrastructure.*`) are kept working. The mixed `wardrobe/__init__.py` is split only where it pays: the Pillow composer (`LocalComposer`, `OutfitBrief`, `Renderer`, `_validate_brief`, `CATEGORIES`) moves to `wardrobe/composer.py` and is re-exported from `wardrobe/__init__.py` (same public names; `WardrobeAgent.generate` still calls `_validate_brief`, and `tests/test_wardrobe.py` imports the private `_safe_root`/`_safe_target` from `mascot_wardrobe.wardrobe`, so those must stay importable there). The ADR must describe whatever is actually done.

## Step 2: Original artwork and reproducible generator

Single source of truth in code: `art/generate_art.py` (Pillow only, no new dependency, no network) defines the creature as a list of shapes (rounded body, head, ears, cheeks, eyes, belly, feet in cream `#FFF4DC`, mint `#BFE8D5`, coral `#FF8A7A`, ink `#33415C`) and emits both an editable SVG (`art/mascot.svg`, hand-readable `<g id="...">` groups, comments, no raster embedding) and a supersampled transparent PNG (`examples/mascot.png`, 512x512 RGBA, head region fully above the default body box so outfits never cover face pixels). It also renders `assets/hero.png` (1600x500: mascot on a soft mint gradient, restrained title "mascot-wardrobe", tagline "Generate once. Select by weather.", three outfit teasers) and `assets/contact-sheet.png` (six outfits generated through the real `prepare_wardrobe` + `LocalComposer` pipeline, labelled with category and temperature range of the BR preset). Output is deterministic (fixed seed-free geometry, `Image.save` with fixed params); `art/README.md` states authorship ("Mascot Wardrobe contributors, original work") and MIT license. The SVG is parsed in a test with `xml.etree` for well-formedness and required group ids. Font: Pillow's bundled scalable default via `ImageFont.load_default(size=...)` (requires FreeType support in the Pillow build, present in official wheels), so no font files are shipped.

TDD slices: (1) generator is deterministic: running twice into two temp dirs yields identical SHA-256 for all outputs; (2) PNG is RGBA 512x512 with transparent corners and opaque head center; (3) SVG well-formed with ids `body`, `head`, `face`; (4) running `prepare_wardrobe` on `examples/mascot.png` with the default body box produces six outfits with six distinct pixel hashes and pixels outside the body box are byte-identical to the source (head preserved); (5) hero and contact sheet have the documented sizes. The committed art files must equal fresh generator output (test regenerates into a temp dir and compares), which keeps art reproducible. Compare `art/mascot.svg` byte-for-byte and `examples/mascot.png` by decoded RGBA pixel bytes (PNG zlib output may differ across Pillow versions in the CI matrix, since `Pillow>=11,<14` is unpinned). For `assets/hero.png` and `assets/contact-sheet.png`, which contain text rasterized by the FreeType bundled with each Pillow wheel, only assert size and run-twice determinism in the same environment; do not compare against the committed file in CI. `art/` is not importable (`pythonpath = ["src"]`), so tests run the generator via `subprocess` with `sys.executable` or load it with `importlib.util.spec_from_file_location`.

Files created: `art/generate_art.py`, `art/mascot.svg`, `art/README.md`, `examples/mascot.png`, `assets/hero.png`, `assets/contact-sheet.png`, `tests/test_art.py`. `art/` is not part of the wheel; the generator imports the installed package for the contact sheet.

Unchanged: package runtime code (no art logic inside `src`).

## Edge cases

- Output path containing `..` or a symlink anywhere in its ancestry: rejected with an English `ValueError`; exit code 2 in the CLI.
- Existing output with different request parameters: generate refuses (manifest mismatch) rather than overwriting.
- Temperature exactly on a boundary: upper category. Fahrenheit 32 F is 0 C. NaN, infinity, bool and out-of-range values rejected.
- Weather payload with naive time: uses `utc_offset_seconds`; missing offset is a malformed-reading error.
- Export channel repeat with identical bytes: `unchanged`, no rewrite (mtime preserved); changed bytes: rewritten atomically and reported as `exported` (FileExportChannel's actual action name; only the HTTP bridge reports `updated`).
- Opaque PNG: overlay is applied inside the body box only, transparency is preserved as-is; documented as a limitation.
